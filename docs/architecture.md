# 工程架构

课程构建一个 Agent Harness 应用，组织模型、工具、执行循环、上下文、会话、权限与评测能力，CLI 是应用入口。具体业务能力由工具、数据和权限配置提供；入门示例不决定运行核心的业务范围。

## 当前实现

采用单个 uv 项目与 `src` 布局，安装包名为 `agent-harness-lab`，Python 导入名为 `agent_harness_lab`。基础 CLI 提供帮助与版本输出；第 01 篇通过 `python -m agent_harness_lab.first_agent` 运行只读工具调用示例。

工程使用 Ruff 检查和格式化、mypy 严格类型检查、pytest 行为测试及 uv 构建。CI 在 Python 3.12 和 3.13 上执行检查；新增 Python 版本需先通过验证。

## 逐步实现的模块

以下为课程演进规划，尚未创建对应运行模块。仅在出现实际实现和测试时新增目录。

| 模块 | 职责 |
| --- | --- |
| `domain` | 消息、工具调用、任务状态和会话事件的数据类型 |
| `runtime` | Agent 循环、停止条件、取消传播和执行预算 |
| `providers` | 模型服务接口及 DeepSeek 适配、流式响应处理 |
| `tools` | 工具声明、参数校验、调用与结构化结果 |
| `sessions` | 事件存储、状态重建及中断恢复 |
| `context` | 模型输入选择、压缩与跨任务记忆 |
| `orchestration` | 工作流、子任务依赖和多 Agent 协作 |
| `observability` | 调用轨迹、耗时、Token 用量和费用记录 |
| `evaluation` | 固定样例评测、结果判定和回归比较 |

## 依赖与装配

领域数据不依赖供应商 SDK、存储或 CLI。运行机制依赖明确的 Python 接口；具体 Provider 和存储实现通过应用入口显式传入。部署相关选项通过配置传递，避免全局可变单例。遇到第二种实现时再提炼共享接口，不预建通用插件框架。

Cordis 不作为 Python 项目依赖。本课程保留职责分离、可替换能力及明确生命周期等设计原则；若以后需要调用 Node.js 组件，另行定义进程或网络协议。

## 可靠性验收

新增能力必须带可执行的验收：模型流式中断可定位，取消能传播到子任务，重试有预算，恢复考虑工具副作用与重复执行，任务和用户数据按权限隔离。一次模型请求应能追踪输入来源、执行结果、耗时和用量；更换模型、Prompt 或 Skill 应运行回归评测。

单元测试默认无网络、无凭据。真实模型测试应独立标记并显式启用；日志、样例和提交不得包含密钥或真实敏感数据。
